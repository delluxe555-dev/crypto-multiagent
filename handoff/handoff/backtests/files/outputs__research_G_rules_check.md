# Step G — 30 channel rules vs. what our system already does (2026-10-25, Europe/Istanbul)

READ-ONLY review. No code, config, ledger, routine or running process was changed; no backtest was run. Only this file was written.
Source of the rules: one crypto channel, pasted by the user (Turkish). **They are the channel's opinions/claims, not verified facts.** Rules 3, 12 (BTC 87,000–87,200), 27 (≈40% cash "in August") and 30 (98k) are explicitly time-specific or unverified; the rest are common trading heuristics without evidence attached. Nothing here says a rule "works"; our own A–F research found no robust edge after costs (registry: 18 hypotheses, ≈1,141 trials), so the prior for any new entry-signal rule is low.

## Key facts about the current system (verified in code)
- Paper trader (no real orders): hourly cycle, MTF (4h trend + 1h entry) must agree, judge confidence ≥ 65, 6-agent debate. **Stop = 2×ATR(1h), target = 3×ATR (single target, no partials), max hold 24h** (`trader.open_position`). The judge's own stop/target are NOT used by the trader (it only takes direction, confidence, reasoning).
- Risk per trade 1% of equity, leverage ≤ 5x (by confidence), margin ≤ 20% of equity per position, `max_concurrent` = **20** in config (README still says 5), daily realized-loss limit 2% (checked only when opening a new position).
- Stop/target are checked every 2 min on live price + 1-minute candle highs/lows (**wick-touch**, stop wins ties). Breakeven rule: at 67% of the way to target, stop moves to entry +0.3% (`be_enabled`, chosen by `be_sim.py`; gain within noise).
- Live ledger: **13/13 positions are SHORT**; stop distances 0.60–4.44% (median 1.86%); at 2026-10-24 20:03 (UTC+3) 8 positions were open at once with margin ≈ 102% of equity and ≈ $70 (7%) at risk. On 10-25 02:35 three correlated positions (ONDO, TRUMP, ETH) were stopped in one monitor pass for −$32 (−3.2%), above the 2% daily limit that is only checked at entry.
- Key levels: `config.key_levels` holds only BTC and ETH key levels; injected into prompts (`KL`: 4h *close* below level = bearish; wick-only does not count) and watched by `keylevels.py` (alerts only, no exit action).
- Data we have in-house: Binance spot 5m (29 coins, ~150 days, OHLCV only), Binance USDT-M perp 15m/1h/4h for 12 pairs from 2020 (OHLCV only; the fetcher discards the taker-volume columns), Gate perp 15m with OI, taker long/short, liquidations (≈21 days, 26 coins), Gate funding history (29 coins) + OKX funding (~96 days), CoinGecko dominance (≈1 month, 719 of 750 rows are approximate backfill), OKX realized liquidations (24h only), Fear&Greed, DefiLlama stablecoin supply.
- Public data checked reachable from this box (HTTP 200 on bulk files, nothing downloaded): `data.binance.vision` **spot klines** (these include taker-buy volume → spot CVD proxy), **futures `metrics`** (5-min OI, taker long/short volume ratio, long/short ratios; daily files exist back to 2021-01), **futures fundingRate** monthly files. **`liquidationSnapshot` files: 404** (no historical realized liquidations from there). Coinbase: public candles are OHLCV only (no taker side); historical trade-side CVD is not available. None of these are fetched yet.

## Top 5 gaps that matter for risk (ordered)
1. **Aggregate/correlated exposure is uncapped** (rules 8, 10, 27, 26). No total open-risk cap, no BTC-beta/direction cap, `max_concurrent` = 20 (README says 5), margin can reach ~100% of equity. Evidence in our own ledger: 13/13 shorts, 8 open at once (≈7% of equity at risk), and three correlated stops at 10-25 02:35 cost −3.2% in one pass, past the 2% daily limit (which is only checked at entry). Fix candidates are pure risk rules (cap open risk, cap same-direction exposure, cash floor) — they need no edge claim.
2. **No BTC/market regime filter for alt and majors trades** (8, 9, 30). BTC key level is only seen by BTC/ETH prompts; dominance tracker is not connected.
3. **No post-loss cooldown and no intraday-floating loss check** (26). Daily loss limit is realized-only and entry-time-only.
4. **Exits ignore structure, event time and the judge** (16, 17, 22–24, 29). The judge's structure-based stop/target is discarded; the trader uses a flat 2×ATR / 3×ATR with wick-touch stops, no partials, no level+time exit. Live sample so far (12 closed): 6 stops, 3 targets, 3 timeouts — too few to judge whether this costs anything.
5. **No macro-event guard** (29) — no FOMC/CPI calendar, so new leveraged positions can open right before known high-volatility events. (Related data gap: no spot-flow/CVD input at all — rule 2/7 — so the sentiment agent sees only futures-side flow.)

## Testable rules worth a backtest (NOT run; proposed order)
Discipline for all of them: register hypotheses and call `H.add_trials(...)` BEFORE running; fix the definitions up front (no tuning loop); evaluate with the existing machinery (day-block bootstrap, Holm, DSR with N = current registry total ≈ 1,141 + new trials, random-entry baseline, 0.05%/0.15% per side costs). Exits/risk rules should be judged by drawdown and R-distribution shape, not by hunting for a mean-return "edge".
1. **Rule 8 BTC-regime filter (post-hoc, cheapest):** re-slice `trades_r2.npz` and `trades_ict.npz` by BTC state (e.g. BTC above/below 4h/1d EMA or prior swing high) — 1–2 pre-registered variants, no new data.
2. **Rules 2 / 7 / 12 spot-vs-futures CVD:** download Binance spot klines (taker-buy volume) and futures `metrics` (taker ratio, OI) for the 12 ICT pairs (and ideally the 29-coin set) back to 2021; test one pre-defined divergence signal (price up + spot CVD down) and the "long-liq flush + spot CVD not falling" bounce. This is the only signal family in the channel's list that we have never measured.
3. **Rules 4 / 5 funding × price trend and funding × OI:** Binance funding files + `metrics` OI (years). 2–3 pre-registered definitions. Contrarian-funding-alone already showed nothing robust.
4. **Rules 16 / 17 / 18 exit comparison:** same fixed entries (random-entry baseline and the E setups), compare wick stop vs 4h-close stop vs level+time stop vs fixed-% stops 0.75–1.5% / 5–7.5% — report max drawdown, tail loss, give-back.
5. **Rules 22–25 partial exits (90/10, 70/30 + BE, mid-target):** simulate on the same entries; expectation is reshaped variance, not new edge.
6. **Cheap extras:** rule 26 loss-streak cooldown on existing trade tables; rule 29 FOMC days (hard-code the Fed calendar; small sample, treat as descriptive); rules 1/13 break+retest-hold and higher-low confirmation vs plain entries; rule 11 BB-squeeze-alone baseline (check combo set first so trials aren't double counted).
- **Not worth testing now:** #3 Coinbase (only a premium proxy possible, and it is the channel's unverified claim), #9 dominance (≈1 month of data), #27 cash %, #14, #21, #28.

## Honest caveats
- Prompt-level "implemented" items depend on LLM behaviour (free-tier models, non-deterministic); they are not enforced rules.
- Several rules are written for spot swing trading (days–weeks, % stops, cash share); our trader is intraday leveraged-perp style (1h, ATR stops, 24h cap) — transferring numbers like 0.75–1.5% / 5–7.5% or 40% cash is a different regime.
- A–F history: 1,141 trials, no config survived multiple-testing correction. Expect most of the entry-type rules above to also show nothing; the realistic value is in the risk-rule items (gap 1–3), which don't need an edge to be worth having.
- No radar/ folder or glossary file exists; if the user keeps one elsewhere (not on this box), it was not reviewed.
